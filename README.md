# SoloPutt

ZeroPuttの非公式Webクライアントです。ブラウザで機器に接続して、固定距離または上限付きランダム距離でパッティングを練習できます。平坦なグリーンの物理モデルでカップインを判定し、軌道と残り距離を表示します。

## 試し方

1. ZeroPuttの電源を入れ、使用中の公式アプリや別のBLEクライアントを切断する。
2. iPadのBluefy、またはMacのChromeで同じHTTPSページを開く。
3. 「ZeroPuttに接続」を押して機器を選び、「計測準備完了」を待つ。
4. 練習メニューと距離を指定し、「目標を適用」を押して打つ。通信の確認には「接続診断」を使う。
5. 「統計」で距離別のカップイン率と履歴を確認する。練習に戻ったら再接続する。

機器の選択画面にZeroPuttが出ない場合は、ほかのアプリとの接続を切り、「絞り込みなしで探す」を試してください。MacのChromeでは **システム設定 → プライバシーとセキュリティ → Bluetooth** でGoogle Chromeの許可も確認します。

## 機器設定

接続後に「機器設定」を開くと、本体から現在値を読み取ります。スクリーンモードのグリーン速度を変更するには、選択肢から速度を選び「本体に保存」を押してください。読み戻しの結果を画面に表示します。

## 練習と記録

- 固定距離は指定距離を繰り返します。ランダムでは0.5 mから指定距離までの0.1 m刻みで次の目標を選びます。
- 打ち切りは指定距離から始め、ミスなら残り距離から続けます。カップインか1 m未満のOKで終了し、OKは実打に1打足します。判定不能の球は打ち直しです。統計には完了した練習の打数が残ります。
- 判定は本体の推定転がり距離・角度・スティンプ相当値を入力に、[Penner (2002)](https://doi.org/10.1139/p01-137) の式(23)とカップ円への最初の交差を使います。入らずにカップから1 m未満で止まった球は「OK圏内」として区別します。角度エラーの候補値など、判定できない球は各率の計算から除きます。
- 受信したショットと目標・判定をIndexedDBに保存します。統計は期間と練習メニューで絞り込めます。日別の傾向、0.5 m刻みの目標距離帯、左右の打ち出し角、ショート・オーバーの分布を集計し、個別履歴は新しい順に50球ずつ表示します。履歴はブラウザとサイトごとに分かれます。

## CSVで履歴を移す

統計ページの「CSVを書き出す」は絞り込みに関係なく全履歴を出力します。「CSVを取り込む」は既存の履歴に追加し、日時を含む全項目が一致する球をスキップします。別のブラウザへ移すときは、書き出したファイルをそのまま取り込めます。

CSVはUTF-8です。列名は書き出したファイルをひな形にしてください。日時はミリ秒付きのISO 8601 UTC、距離はm、角度は°、速度はm/sで、`greenSpeed`は本体のスティンプ相当値（cm）です。`remaining`は本体の受信値、`leave`はSoloPuttで計算した停止位置からカップまでの距離です。打ち切りモードにはラウンド識別子と打数の列が付き、従来のCSVも取り込めます。

テスト用データを1000球生成するには、リポジトリのルートで次を実行します。第1引数が球数、第2引数が乱数シードです。同じシードで同じCSVを再生成できます。実打の集計と分けて試す場合は、別のブラウザプロファイルで取り込んでください。

```sh
node scripts/generate-shots.mjs 1000 42 > sample-shots.csv
```

## ディレクトリ構成

```text
site/
  index.html       練習・機器設定
  stats/           統計・ショット履歴
  about/           プロジェクト情報
  assets/css/      スタイル
  assets/js/       BLE通信・練習・保存のJavaScript
scripts/           テスト用CSVの生成
tests/             通信・物理モデル・統計・CSVのテスト
.github/workflows/ GitHub Pagesの配信設定
```

GitHub Pagesではリポジトリ名がURLのパスに入るので、ページやアセットへの参照は各ページからの相対パスを使います。

## ローカル実行

MacのChromeで開発する場合は、リポジトリのルートで次を実行して `http://localhost:8000/` を開きます。

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory site
```

## GitHub Pagesで公開

1. リポジトリの **Settings → Pages → Build and deployment** で **Source** を **GitHub Actions** に設定します。
2. ワークフローを含む変更を `main` にpushします。設定より先にpushした場合は、**Actions → Deploy GitHub Pages → Run workflow** で `main` を選んで実行します。
3. デプロイが成功したら、**Settings → Pages** に表示されるHTTPSのURLを開きます。iPadではBluefyで開きます。

ワークフローはNode.jsでテストを実行し、成功すると `site/` の中身だけを公開します。公開URLの入口は `site/index.html` です。

## 通信の概要

カスタムGATTサービスの通知を購読し、ASCIIの改行区切りで通信します。`6` への応答を受けて1秒待ち、`2` を送ります。設定応答 `3,...` を受けると計測準備完了です。計測通知 `0,...` に `9`、`B` に `B` を返します。UUIDと通知の各フィールドは [protocol.mjs](site/assets/js/protocol.mjs) にあります。

## テスト

プルリクエストではGitHub Actionsの **Tests** が自動で実行されます。**Actions → Tests → Run workflow** からテストだけを手動実行できます。GitHub Pagesへの公開前にも同じテストを実行します。

ローカルではNode.js 24以降で実行できます。

```sh
node --test 'tests/**/*.test.mjs'
```
